## 0. الأساسيات

- **Base URL (بيئة التطوير/الاختبار — هذا ما يجب أن يربط به تطبيق فلاتر أثناء التطوير):**
  `https://manara-backend-dev.onrender.com`
  هذا سيرفر منفصل تمامًا عن أي نطاق إنتاج/main حالي أو مستقبلي. لا تُغيَّر هذه القيمة من الفلاتر بدون تنسيق مسبق.
- **الفورمات:** JSON في كل الطلبات والردود، عدا `POST /speak` الذي قد يرجع صوت MP3 خام (انظر تحته).
- **الترميز:** UTF-8، والنصوص عربية.
- **المصادقة (Auth) — ⚠️ تغيّرت جزئيًا 2026-10-01:** لا يوجد مفتاح/توكن عام مطلوب على مسارات الطفل (`/agent/*`، `/speak`) — يبقى تطبيق فلاتر يناديها كالسابق بدون أي هيدر إضافي. CORS لا يخص فلاتر أصلًا (قيد متصفح فقط، تطبيق Flutter الأصلي native لا يمر به إطلاقًا). لكن أُضيفت طبقتان محدودتان:
  - **`X-Admin-Key`**: كل مسارات `/agent/admin/*` و`/agent/pilot-report` تتطلبه الآن (401 بدونه، 503 إذا لم يُضبط `MANARA_ADMIN_KEY` على السيرفر). **لا علاقة له بتطبيق فلاتر إطلاقًا** — مذكور هنا للعلم فقط.
  - **`X-Device-Token` (اختياري/إضافي، جديد)**: لا يكسر أي تطبيق قائم. أي `device_id` لم يُطالَب (claim) بتوكن له يستمر يعمل بدون أي تغيير. لتفعيل الحماية الإضافية: نادي `POST /agent/device-token` مرة واحدة لكل جهاز بـ `{"device_id": "..."}`، يرجع توكن يُعرض مرة واحدة فقط (احفظيه عبر `shared_preferences` فورًا؛ محاولة ثانية لنفس `device_id` ترجع 409). بعدها، أي نداء لـ `/agent/actions/done` لنفس الجهاز يتطلب ترويسة `X-Device-Token: <التوكن>` (401 بدونه أو بتوكن خاطئ). **لا حاجة لفعل أي شيء إن لم تحتاجي هذه الحماية الآن.** انظر مثال Dart كامل في §7.5.
  - **حدود طلبات (Rate Limiting)، جديدة**: `/agent/start`/`/agent/taseem/start`/`/agent/htaseem/start` محدودة بـ 10 طلبات/دقيقة لكل IP، `/agent/message` بـ 30/دقيقة، `/agent/score-recitation` بـ 20/دقيقة. تجاوز الحد يرجع `429 {"detail": "طلبات كثيرة جدًا، حاول بعد قليل من فضلك."}` — عالجيه بنفس منطق معالجة 404 (رسالة لطيفة + إعادة محاولة بعد قليل).
- **الجلسات (Sessions):** لا توجد قاعدة بيانات جلسات دائمة — الجلسة تعيش في ذاكرة السيرفر (in-memory) فقط، وتُحذف تلقائيًا بعد 6 ساعات من عدم الاستخدام، أو حين تتجاوز عدد الجلسات المفتوحة 500 جلسة (يُحذف الأقدم). **معنى ذلك عمليًا لتطبيق فلاتر:**
  - لو أعاد Render تشغيل السيرفر (deploy جديد، أو إعادة تشغيل تلقائية بسبب عدم نشاط في الخطة المجانية)، تُفقد كل الجلسات المفتوحة فورًا.
  - يجب أن يتعامل تطبيق فلاتر مع رد `404 session expired, please start again` من `/agent/message` أو `/agent/score-recitation` بإعادة استدعاء `/agent/start` من جديد بدل اعتباره خطأ فادحًا.
- **`device_id`:** حقل نصي يولّده تطبيق فلاتر (أي معرف ثابت للجهاز/الطفل) ويرسله دائمًا مع `/agent/start`. **مهم جدًا** لأنه المفتاح الوحيد الذي يربط:
  - تقدّم الحفظ عبر الجلسات (`/agent/progress`, يتابع أي سورة/جزء وأي حديث انتهى منه الطفل)
  - ملاحظات الشخصية التراكمية (ما يتعلمه المعلّم عن أسلوب الطفل عبر الجلسات)
  عدم إرساله يعني أن كل جلسة تبدأ من الصفر بدون أي ذاكرة سابقة.

## 1. مسار المحادثة الموجَّهة — `/agent/*`

هذا هو الـ API الحي والوحيد الذي يجب أن يربط به تطبيق فلاتر. آلية العمل: **آلة حالات محددة مسبقًا (deterministic state machine)** — لكل جلسة مسار ثابت من المراحل (stages)، والمعلّم يتقدّم فيها مرحلة مرحلة. المحتوى الديني (آيات، تفسير، أحاديث) ثابت من ملفات مراجَعة، وذكاء LLM يُستخدم فقط لصياغة الكلام الاجتماعي والإجابة عن أسئلة الطفل الجانبية — **لا يُستخدم لإنتاج أي نص قرآني أو حديثي بحد ذاته.**

يوجد مساران (modes):

| Mode | القيمة المرسلة | المراحل (stages) بالترتيب |
|---|---|---|
| القرآن | `"quran"` (افتراضي) | `greet → surah → lesson_intro → tafsir → fadl → recitation → tajweed → plan → done` |
| الحديث | `"hadith"` | `greet → intro → text → words → meaning → example → memorize → quiz → action → done` |

⚠️ **لا توجد مرحلة `name` منفصلة في أي من المسارين** (كانت موجودة سابقًا ثم أُزيلت — طلب سابق من رزان لتقصير المسار). اسم الطفل يُرسَل مباشرة كحقل `child_name` في `POST /agent/start`؛ إن أرسله الطفل لاحقًا بصوته/كتابةً بدل ذلك، يلتقطه المعلّم ضمن مرحلة `greet` نفسها دون مرحلة مستقلة له.

مسار القرآن محصور حاليًا بـ 3 سور فقط (نطاق تجريبي — pilot)، تُعرَض دائمًا بهذا الترتيب: **الإخلاص ← الناس ← الفلق**. مسار الحديث محصور بـ 3 أحاديث: **بر الوالدين ← الكذب ← لا تغضب**. أي اسم سورة/حديث آخر يقوله الطفل يُرَدّ عليه بلطف بأنه "قريبًا" بدل تعليمه فعليًا.

### POST /agent/start

يبدأ جلسة جديدة.

**Body:**
```json
{
  "child_name": "أحمد",     // اختياري، افتراضي "يا بطل" — هذا الاسم يُستخدم مباشرة طوال الجلسة في كلا المسارين (لا توجد مرحلة "name" منفصلة تسأل الطفل عن اسمه — انظر التنويه أعلى الجدول)
  "mode": "quran",          // اختياري: "quran" أو "hadith"، افتراضي "quran"
  "gender": "boy",          // اختياري، افتراضي "boy". القيم التي تُفهم كـ "بنت": "girl", "female", "f", "بنت", "أنثى", "انثى" (غير حساس لحالة الأحرف). أي قيمة أخرى (أو فارغة) = ولد
  "device_id": "abc123"     // اختياري لكن يُنصح بإرساله دائمًا — انظر أعلاه
}
```

**Response:** كائن جلسة كامل (انظر "شكل الرد" تحت) بمرحلة `greet`.

⚠️ ملاحظة جندر مهمة: عند `gender: "girl"` يستخدم المعلّم اسم "المعلمة سارة" بدل "المعلم عبدالله" في كل الجلسة، مع تصريف نحوي مؤنث. هذا يشمل حتى الأزرار السريعة (`quick_replies`). لا حاجة للفلاتر لفعل أي شيء إضافي غير إرسال `gender` الصحيح.

### POST /agent/message

يرسل رد الطفل (نص) ويستقبل رد المعلّم التالي.

**Body:**
```json
{
  "session_id": "الآيدي المُستلَم من /agent/start أو أي رد سابق",
  "text": "كلام الطفل هنا",
  "mode": null   // غير مستخدم فعليًا من السيرفر حاليًا؛ السيرفر يحدد المسار (قرآن/حديث) تلقائيًا من session_id نفسه. يمكن للفلاتر إرسال null أو تجاهل هذا الحقل بأمان
}
```

**Response:** نفس شكل رد `/agent/start` لكن بالمرحلة الجديدة.

**خطأ محتمل:** `404 {"detail": "session expired, please start again"}` — الجلسة غير موجودة (انتهت صلاحيتها أو أعاد السيرفر التشغيل). التعامل الصحيح من الفلاتر: نداء `/agent/start` من جديد وإخبار الطفل بجملة لطيفة (مثل "خلنا نبدأ من جديد").

### POST /agent/score-recitation

تقييم صوتي اختياري للتلاوة/الحفظ. **⚠️ تغيّر مزوّد هذه الخدمة بالكامل بتاريخ 2026-09-30: كانت RunPod (Whisper + نموذج تقييم تلاوة مخصص)، وأصبحت الآن Groq (`whisper-large-v3-turbo`، خدمة نسخ صوت سحابية مجانية وسريعة جدًا)** — رزان أوقفت RunPod نهائيًا بسبب مشاكل الفوترة/التشغيل. RunPod لم يعد مستخدمًا إطلاقًا في الكود الحي (الملف القديم `app/services/runpod_asr.py` باقٍ في المستودع لكن غير مستدعى من أي مكان). **هذا المسار منفصل تمامًا عن `/agent/message`** — يُستخدم فقط حين تكون `expects == "repeat"` في آخر رد (انظر تحت)، أي حين يكون المطلوب من الطفل ترديد آية أو حديث بصوته لا كتابة نص.

**Body:**
```json
{
  "session_id": "...",
  "audio_base64": "تسجيل صوتي مُرمَّز base64 — Groq يتعرّف تلقائيًا على صيغة الملف من محتواه، فهذا يعمل بأي صيغة يسجّلها المتصفح (webm;codecs=opus, webm العادي, mp4)، لا حاجة لتحويل مسبق"
}
```

**Response — حالتان:**

1. **الخدمة غير مُفعّلة على السيرفر** (متغيّر البيئة `GROQ_API_KEY` غير مضبوط على Render) أو فشل الاتصال بـ Groq لأي سبب (شبكة، حصة، مهلة):
   ```json
   {"available": false}
   ```
   في هذه الحالة **يجب على الفلاتر عدم الاعتماد على هذا المسار إطلاقًا** والاستمرار بالتدفق العادي (التقييم النصي الداخلي البسيط الذي يقارن كلام الطفل بالمرجع، ويحدث تلقائيًا أيضًا عبر `/agent/message` كخط أول حتى لو كان Groq مفعّلاً — انظر الملاحظة تحت).

2. **نجح التقييم** — الحقول هنا الآن **معروفة ومضبوطة من هذا المستودع نفسه** (`app/services/groq_asr.py`، وليست خارجة عن السيطرة كما كانت مع RunPod):
   ```json
   {"available": true, "transcription": "النص الذي سمعه Groq من صوت الطفل", "score": 0.82, "tajweed_errors": ["..."]}
   ```
   - `transcription` (نص): تفريغ Groq الفعلي لصوت الطفل — **هذا هو الحقل الوحيد الذي تستخدمه واجهة الويب الحالية فعليًا** من هذا الرد (`if(j.available && j.transcription) send(j.transcription)`، ثم يُعامَل كأنه نص الطفل ويُرسَل إلى `/agent/message` كالمعتاد).
   - `score` (رقم 0 إلى 1) و`tajweed_errors` (قائمة نصوص): مقارنة نصية تقريبية (`difflib`) بين `transcription` والنص المرجعي المتوقع — **موجودة للتسجيل الداخلي فقط حاليًا** (تُحفظ في جدول `manara_voice_samples` لأغراض لاحقة)، **وواجهة الويب لا تقرأها ولا تعرضها للطفل إطلاقًا**. تطبيق فلاتر حرّ في استخدامها إن أراد عرض تقييم تجويد للطفل، لكن يجب معرفة أنها تقريبية (مطابقة نصية بسيطة) وليست تحليل تجويد صوتي حقيقي.
   - ⚠️ **ملاحظة دقة:** Groq يستخدم موديل Whisper عام متعدد اللغات، **غير مدرَّب خصيصًا على التلاوة القرآنية** (بخلاف موديل `tarteel-ai/whisper-base-ar-quran` المتخصص الذي كان مخططًا سابقًا). التفريغ عمومًا دقيق للعربية الفصحى الواضحة، لكن لا تتوقعوا دقة متخصصة في نطق حروف التجويد.

**ملاحظة معمارية مهمة:** التدفق الأساسي (`/agent/message`) لا ينتظر أبدًا هذا المسار — تقييم التلاوة النصي البسيط (مطابقة تقريبية للنص) يحدث فورًا ومحليًا داخل `/agent/message` نفسه بمجرد أن يرسل الطفل نصًا في مرحلة `recitation`/`memorize`. مسار `/agent/score-recitation` هذا **إضافي (optional enhancement)** فقط حين يتوفر صوت فعلي من الطفل، وليس شرطًا لعمل التطبيق. Groq سريع جدًا (نسخ يقارب 200 ضعف السرعة الحقيقية)، فالبطء الوحيد المتبقي هو زمن الشبكة نفسه — لا يوجد انتظار لخدمة GPU خارجية بطيئة كما كان الحال سابقًا.

### GET /agent/status

فحص سريع لحالة الذكاء الاصطناعي (مفيد لشاشة تشخيص/دعم فني داخل الفلاتر إن أردتم، ليس ضروريًا للمستخدم النهائي).

**Response:**
```json
{"llm": true, "model": "claude-sonnet-4-5", "last_error": null}
```

### GET /agent/content

قائمة أولية بمحتوى الدرس الافتراضي (الفاتحة) و5 أحاديث. **ليست ضرورية لتشغيل المحادثة** — المحادثة نفسها (`/agent/start` + `/agent/message`) تُرسل كل ما يحتاجه الطفل من نص ضمن حقل `say` مباشرة. هذا المسار مفيد فقط لو أراد الفلاتر عرض قائمة/فهرس منفصل خارج المحادثة (مثلاً شاشة "اختر حديثًا" مسبقًا).

⚠️ **تنويه دقة مهم:** هذا المسار يقرأ من ملف قديم منفصل (`app/services/lesson_content.py`)، **وليس** من المحتوى الفعلي الذي يستخدمه مسار الحديث الحي (`app/services/hadith_content.py`، 10 أحاديث، فيها حقول `gharib`/`action`/`dorar_ref`/`dorar_grade`). أي: لا تعتمدوا على هذا المسار لعرض قائمة الأحاديث الحقيقية أو مرجع الدرر السنية — هذا الحقل غير معروض حاليًا عبر أي API إطلاقًا (موجود فقط في الكود وفي كلام المعلّم حمود صوتيًا). إن احتاج الفلاتر لاحقًا لعرض قائمة الأحاديث الحقيقية (بما فيها مرجع التحقق)، هذا يحتاج تعديلًا بسيطًا على هذا المسار — ننسّق عليه وقتها.

### GET /agent/surahs

قائمة كل السور الـ 114 (`{"surahs": [{"n": 1, "name": "الفاتحة", "count": 7}, ...]}`) — **لكن الدرس الفعلي حاليًا مقصور على 3 سور ضمن نطاق التجربة التجريبية (pilot): الإخلاص (112)، الناس (114)، الفلق (113) — بهذا الترتيب بالذات، وليس بترتيب الأرقام** (`pilot_config.PILOT_SURAH_ORDER = [112, 114, 113]`، المصدر الوحيد للترتيب في كل مكان يظهر فيه)، بالإضافة لسورة الفاتحة كدرس تعريفي أول. طلب أي سورة أخرى من مرحلة `surah` يُرجع ردًا لطيفًا "رح نتعلمها قريبًا" بدل تدريسها فعليًا. لا تعرض كل الـ 114 سورة كخيارات فعّالة — التزم بترتيب `quick_replies` في رد مرحلة `surah`.

⚠️ نفس المبدأ للحديث: `pilot_config.PILOT_HADITH_ORDER = [9, 10, 6]` (بر الوالدين ← الكذب ← الغضب) — `hadith_agent.py` يفرز قوائمه بهذا الترتيب دائمًا.

### GET /agent/progress?device_id=...

ملخص تقدّم الطفل المحفوظ عبر الجلسات (مطلوب `device_id`، وإلا يرجع فارغًا):
```json
{
  "quran": {"completed_chunks": ["2:0", "112:0"]},
  "hadith": {"completed": ["1", "3"]}
}
```
مفيد لعرض شارات/تقدّم في شاشة رئيسية بدون الحاجة لبدء جلسة.

### ⚠️ مسارات لم تكن موثَّقة هنا سابقًا (موجودة في الكود منذ فترة، أُضيفت لهذا التوثيق الآن فقط)

#### التسميع (اختبار الحفظ بعد يوم) — `/agent/taseem/*` (قرآن) و`/agent/htaseem/*` (حديث)

فكرة منفصلة تمامًا عن مسار التعلّم العادي: بعد أن يُنهي الطفل حفظ سورة/حديث بالكامل، يصير "جاهزًا" لاختبار تسميع (سرد من الحفظ بدون تلقين) **بعد مرور 24 ساعة على الأقل** من إتمامه — وليس في نفس الجلسة.

- **`GET /agent/taseem/status?device_id=...`** → `{"items": [{"item_key": "2:0", "ready": true, "hours_since": 30.5, "last_score": 0.9, "surah_no": 2, "chunk": 0, "title": "...", "meta": "..."}]}` — كل سورة/جزء أنهاه الطفل فعلاً، مع `ready` (هل مضى يوم كامل عليه) و`hours_since` و`last_score` (آخر درجة تسميع سابقة، أو `null` إن لم يُختبر من قبل). اعرضوا زر "تسميع" فقط للعناصر التي `ready: true`.
- **`GET /agent/htaseem/status?device_id=...`** → نفس الشكل لكن بحقول `hadith_id`/`title` بدل `surah_no`/`chunk`/`meta`.
- **`POST /agent/taseem/start`** `{"device_id", "gender", "surah_no", "chunk"}` → يبدأ جلسة تسميع، يرجع نفس شكل رد المحادثة العادي (`say`/`expects`/`actions`/`quick_replies`) لكن **`kind: "taseem"`**، و`stages` هنا تمثّل آيات هذا الجزء فقط (مو مراحل الدرس الكاملة) — ⚠️ لا يوجد فيه `stage`/`profile`/`child_name`/`llm` كما في رد المحادثة العادي.
- **`POST /agent/htaseem/start`** `{"device_id", "gender", "hadith_id"}` → مثله لمسار الحديث، **`kind: "htaseem"`**.
- المتابعة بعد `start` تكون عبر **نفس** `POST /agent/message` المعتاد بـ `session_id` الجلسة الجديدة (السيرفر يتعرّف تلقائيًا أنها جلسة تسميع لا جلسة تعلّم عادية) — لا حاجة لمسار `/message` منفصل. وكذلك `POST /agent/score-recitation` يعمل معها بنفس الطريقة (`expects=="repeat"`).
- عند الانتهاء: رد بـ `expects: "none"` يحتوي الدرجة النهائية ضمن `say` نصيًا (مثال: "درجتك في هذا التسميع: 82 من 100")، ويُسجَّل تلقائيًا في تقدّم الطفل.

#### مشاريعي التطبيقية — `GET /agent/actions?device_id=...` و`POST /agent/actions/done`

كل حديث في `hadith_content.py` يحمل حقل `action` (توجيه تطبيقي عملي، مثلاً "ابتسم اليوم لثلاثة أشخاص"). هذا المسار يبني منه شاشة "مشاريعي" — بطاقة لكل حديث أتمّ الطفل حفظه فعلاً:

```json
{"items": [{"hadith_id": 9, "title": "بر الوالدين", "action": "ساعد أمك أو أباك اليوم بشيء بسيط، وقل لهما: أحبكما.", "done": false}]}
```

`POST /agent/actions/done` `{"device_id", "hadith_id"}` → `{"ok": true}` — الطفل (أو وليّ أمره) يعلّم أنه نفّذ التوجيه فعلاً. هذه علامة "تم" بسيطة، لا يتحقق منها السيرفر فعليًا (ثقة، لا رقابة).

⚠️ **(جديد 2026-10-01)** إذا كان هذا الجهاز قد طالَب بتوكن عبر `POST /agent/device-token` سابقًا (انظر قسم المصادقة في §0 ومثال §7.5)، هذا الطلب يتطلب الآن ترويسة `X-Device-Token: <التوكن>` — بدونها أو بتوكن خاطئ يرجع 401. إذا لم تُفعّلي نظام device-token لهذا الجهاز، لا شيء يتغيّر.

#### القفز بين المراحل — `POST /agent/jump`

```json
{"session_id": "...", "stage": "fadl"}
```

يسمح للطفل (عبر زر رجوع في الشريط الجانبي مثلاً) بالرجوع لمرحلة **سبق ووصلها فعلاً** في نفس الجلسة لمراجعتها — لا يمكن أبدًا القفز **قُدُمًا** لمرحلة لم يصلها بعد (السيرفر يتجاهل الطلب بصمت ويعيده لمكانه الحالي إن حاول ذلك). الرد بنفس شكل رد `/agent/message` العادي. يعمل مع مسار القرآن ومسار الحديث كليهما (السيرفر يتعرّف تلقائيًا من `session_id`).

## 2. شكل الرد الكامل (من `/agent/start` و`/agent/message`)

```jsonc
{
  "session_id": "hex string — احفظه وأرسله في كل نداء لاحق",
  "kind": "hadith",            // ⚠️ يظهر فقط في مسار الحديث! غائب تمامًا في مسار القرآن (انظر التحذير تحت)
  "teacher": "المعلم عبدالله", // أو "المعلمة سارة" — اسم المعلّم الحالي حسب الجندر
  "female": false,             // true لو الجلسة بصيغة مؤنثة
  "stage": "greet",            // معرّف المرحلة الحالية (انظر جدول المراحل أعلاه)
  "stage_index": 0,            // رقم المرحلة (0-based) داخل مصفوفة stages
  "stages": [{"id": "greet", "label": "الترحيب"}, "..."],  // كل المراحل بالترتيب مع تسمية عربية لكل واحدة — يمكن استخدامها لعرض شريط تقدّم
  "say": "السلام عليكم! أنا المعلم عبدالله. كيف حالك يا بطل؟",  // النص الذي يجب أن يُقرأ/يُسمع للطفل (عبر /speak أو صوت الجهاز)
  "actions": [ /* انظر جدول actions تحت */ ],
  "expects": "text",           // ما الذي يُنتظر من الطفل — يحدد سلوك واجهة الفلاتر (انظر تحت)
  "quick_replies": ["الحمد لله بخير", "تمام"],  // اقتراحات أزرار جاهزة (اختيارية العرض، النص الحر يعمل دائمًا أيضًا)
  "profile": {"name": "أحمد", "surah": "الإخلاص"},  // ⚠️ منذ إزالة مراحل name/age/why/purpose، الحقل الوحيد المضمون هنا هو "name" (من child_name)؛ حقل "surah" يُضاف فقط في مسار القرآن بعد اختيار السورة. لا تتوقعوا "age" — لم يعد يُجمَع إطلاقًا
  "child_name": "أحمد",
  "llm": true,                 // هل الذكاء التوليدي مفعّل حاليًا على السيرفر (معلوماتي فقط)
  "recitation_scores": [{"ayah": 1, "score": 0.95, "tries": 1}],  // أو {"hadith": id, ...} في مسار الحديث
  "lesson_title": "الفاتحة",   // مسار القرآن فقط
  "surah_no": 1                // مسار القرآن فقط
}
```

### ⚠️ فخ توثيقي مهم: حقل `kind`

- في **مسار الحديث** فقط: كل رد يحتوي `"kind": "hadith"`.
- في **مسار القرآن**: حقل `kind` **غير موجود إطلاقًا** في الرد (ليس `null`، بل غائب تمامًا).

**لا تعتمد الفلاتر على وجود/قيمة `kind` لمعرفة أي مسار هي فيه.** بدل ذلك: تطبيق فلاتر يعرف المسار من القيمة التي أرسلها بنفسه في `mode` عند نداء `/agent/start`، ويحتفظ بها محليًا (مثلاً في حالة الشاشة) طوال الجلسة. هذا أبسط وأضمن وأصح من قراءة `kind` من الرد.

### قيم `expects` وسلوك الواجهة المتوقع

| القيمة | المعنى | ما يجب أن تفعله الواجهة |
|---|---|---|
| `"text"` | ينتظر إجابة نصية حرة (اسم، عمر، إلخ) | حقل إدخال نص / أو تحويل الصوت لنص عبر تعرّف صوت الجهاز نفسه، ثم إرساله كنص لـ `/agent/message` |
| `"continue"` | ينتظر فقط "أكمل/تمام" أو سؤالًا جانبيًا | زر "أكمل" + إمكانية سؤال حر (كلاهما نص عادي إلى `/agent/message`) |
| `"repeat"` | ينتظر ترديد الطفل لآية/حديث **بصوته** | فتح التسجيل الصوتي وإرساله لاحقًا إلى `/agent/score-recitation` (تقييم صوتي اختياري)، **و/أو** ببساطة تحويل الكلام المسموع إلى نص محلي وإرساله كنص عادي إلى `/agent/message` (التقييم النصي البسيط سيعمل تلقائيًا) — الخياران صحيحان، الثاني أبسط وأسرع وهو ما يعتمد عليه التطبيق الحالي بشكل أساسي |
| `"choice"` | سؤال اختيار من متعدد (كويز) | تُعرض `quick_replies` كأزرار اختيار؛ اختيار نص الزر يُرسل كما هو نصًا إلى `/agent/message` |
| `"none"` | انتهت الجلسة | لا تنتظر إدخالًا؛ اعرض شاشة/زر "ابدأ جلسة جديدة" الذي يعيد نداء `/agent/start` |

⚠️ **درس مهم من مشكلة واجهة الويب الحالية (تم إصلاحها هناك، انتبهوا له في الفلاتر):** لا تُستخدم أبدًا خدمة التقييم الصوتي الخارجية (`/agent/score-recitation`) كبديل احتياطي لأي مرحلة غير `expects == "repeat"`. استخدامها في غير محلّها هو ما تسبب سابقًا ببطء شديد وتعليق الرد على واجهة الويب.

### أشكال `actions[]`

| `type` | الحقول | الاستخدام |
|---|---|---|
| `show_ayat` | `ayat: [نصوص]`, `first?: رقم أول آية`, `current?: رقم الآية الحالية` | اعرض نص الآية/الآيات (أو نص الحديث، في مسار الحديث تكون `ayat` مصفوفة من عنصر واحد هو نص الحديث) على الشاشة؛ `current` إن وُجد يشير لأي آية يجب تمييزها بصريًا الآن |
| `play_all` | `urls: [روابط mp3]` | شغّل الروابط بالترتيب (تلاوة كاملة لمجموعة آيات) |
| `play_ayah` | `ayah: رقم`, `text: النص`, `url: رابط mp3` | شغّل تلاوة آية واحدة بعينها (تُستخدم في مرحلة الترديد، آية بآية) |
| `set_step` | `step: رقم` | ⚠️ **غير مُستخدَم فعليًا في أي واجهة حالية** (تم التأكد من كود واجهة الويب المرجعية — لا يُقرأ هذا الحقل هناك إطلاقًا). يبدو أنه كان مخططًا كمؤشر تقدّم بصري لكنه لم يُفعَّل. **توصية: تتجاهله الفلاتر بأمان تام حاليًا**، أو ننسق مع مطوّر الذكاء الاصطناعي إن أردتم تفعيله لغرض معيّن مستقبلاً |

روابط الصوت لتلاوة القرآن مصدرها خدمة تلاوة خارجية موثوقة (everyayah.com، صوت الشيخ العفاسي) وليست مُخزَّنة على هذا السيرفر — الفلاتر تشغّلها كأي رابط mp3 عادي عبر مشغل صوت قياسي (لا حاجة لأي معالجة خاصة).

## 3. تحويل النص إلى صوت — `POST /speak` و `GET /speak/status`

### POST /speak

**Body:**
```json
{"text": "النص المراد نطقه (يُقصّ تلقائيًا لأول 1200 حرف إن كان أطول)", "gender": "boy"}
```
`gender`: أي قيمة تحتوي `"girl"` أو `"female"` (case-insensitive) تُستخدم فيها صوت المعلمة سارة، وإلا صوت المعلم عبدالله.

**⚠️ الرد له شكلان مختلفان تمامًا حسب النجاح — يجب على الفلاتر التمييز بينهما عبر الـ Content-Type وليس افتراض شكل واحد:**

- **نجاح:** رد ثنائي خام (binary)، `Content-Type: audio/mpeg`، وهو ملف MP3 جاهز للتشغيل مباشرة. مع هيدر `Cache-Control: public, max-age=86400` (يمكن تخزينه مؤقتًا 24 ساعة على جهاز الطفل لتفادي إعادة الطلب لنفس الجملة).
- **فشل:** رد JSON عادي بأحد هذه الأشكال:
  - `{"audio": null, "note": "empty"}` — النص المُرسل فارغ
  - `{"audio": null, "note": "no_key"}` — لا يوجد مفتاح ElevenLabs مضبوط على السيرفر حاليًا
  - `{"audio": null, "note": "tts_error", "detail": "..."}` — خطأ فعلي أثناء التوليد (شبكة/حصة/إلخ)

**التوصية للفلاتر:** عند أي رد ليس `audio/mpeg`، ارجع لصوت الجهاز المحلي (Text-to-Speech المدمج في iOS/Android) كخطة بديلة فورية، حتى لا يتوقف الدرس بصمت. هذا هو نفس منطق واجهة الويب الحالية.

### GET /speak/status

فحص تشخيصي (هل ElevenLabs مفعّل، أي صوت مُختار):
```json
{"elevenlabs": true, "voice": "معرف الصوت", "how": "account-arabic-male:اسم الصوت", "model": "eleven_multilingual_v2", "female_voice": "معرف صوت المعلمة"}
```
ليس ضروريًا لتشغيل التطبيق، مفيد فقط للتشخيص.

## 4. مسارات مُزالة بالكامل من السيرفر — ⚠️ لم تعد موجودة إطلاقًا (404)

⚠️ **(تغيّر جوهري 2026-10-01)**: المسارات التالية لم تعد مجرد "غير مستخدمة" كما وصفتها نسخة 30 سبتمبر من هذا الملف — تم **فكّ ربطها بالكامل** من التطبيق (`app/main.py`)، وأي طلب لها يرجع **404** الآن:

- **`POST /chat`** (`{student_id?, message}`): كان مسار محادثة عام بسيط منفصل عن `/agent/*`، بدون فحوصات إشراف (moderation) على محتوى يخاطب أطفالاً. **مُزال بالكامل.**
- **`POST /recite`** (`multipart/form-data`): كان مسار قديم لتقييم الأداء على جدول بيانات مختلف تمامًا (`quran_ayat`, `recitation_attempts`, `memorization_progress`). **مُزال بالكامل.**
- **`/api/*`** (`data.py`، بما فيها `/api/students`): نموذج بيانات قديم (`users`, `students`, `lessons`, `recitation_attempts`...). **سبب الإزالة الفعلي: مراجعة أمنية كشفت أن `/api/students` كان يُسرّب `id`/`parent_id` لكل طفل في النظام بدون أي مصادقة (ثغرة IDOR حقيقية).** **مُزال بالكامل.**

تطبيق فلاتر يجب أن يُبنى فقط على مسارات `/agent/*` و`/speak`/`/speak/status` الموثقة في هذا الملف.

## 5. مسارات أخرى موجودة في الكود — ⚠️ لا تُستخدم من الفلاتر

- **`GET /health`**: فحص اتصال قاعدة البيانات فقط، لأغراض تشغيلية (uptime monitoring)، لا علاقة له بمنطق التطبيق.
- **`/agent/admin/*` و`/agent/pilot-report`** (`errors`, `flags`, `embeddings-coverage`, `runpod-stats`, `runpod-log`, `autogen-content(+/reviewed)`, `knowledge(+/approve)`, `pilot-report`): مسارات مراجعة داخلية لصاحبة المنتج/المطوّر فقط. **كلها تتطلب هيدر `X-Admin-Key`** الآن (قيمته = متغيّر البيئة `MANARA_ADMIN_KEY` على Render؛ 401 بدونه، 503 إذا لم يُضبط المتغير إطلاقًا على السيرفر). **لا علاقة لها بتطبيق الطفل إطلاقًا ولا يُنصح بربطها من فلاتر** — هذه لواجهة إدارية/تقرير داخلي فقط. (`runpod-stats`/`runpod-log` تحديدًا أصبحا تاريخيين فقط بعد إيقاف RunPod 2026-09-30، و`pilot-report` لم يكن يتطلب `X-Admin-Key` قبل 2026-10-01 — انتبهوا لذلك إن كان أي كود سابق ينادونه بدون الهيدر.)

إذا احتاج المطوّر لأي من هذه المسارات مستقبلاً، يُفضَّل التنسيق أولاً بدل الافتراض أنها جاهزة/مدعومة.

## 6. ⚠️ تنويه مهم قبل الإطلاق العام: تقييم التلاوة وتخزين صوت الأطفال

**توضيح صريح (بقرار من صاحبة المنتج):** النظام الحالي **يُقيّم فعليًا** تلاوة/حفظ الطفل (تشابه نصي فوري + تقييم صوتي اختياري عبر Groq، سابقًا RunPod)، **ويُخزّن فعليًا** كل تسجيل صوتي يُرسله الطفل في قاعدة بيانات السيرفر (جدول `manara_voice_samples`)، لاستخدامه لاحقًا في تدريب/تقييم نموذج خاص. هذا **قرار منتج متعمّد**، وليس خطأ أو سلوكًا غير مقصود في الكود — تم بناؤه بهذا الشكل عن قصد.

المطلوب فقط، وهذا سبب ذكر النقطة هنا، هو أن هذا النوع من المعالجة (تقييم مباشر لصوت طفل + تخزينه) **يستلزم عادة إفصاحًا رسميًا وموافقة صريحة من ولي الأمر** قبل النشر الفعلي على متاجر التطبيقات — تحديدًا:
- **Google Play "Data Safety"**: تصريح بأن التطبيق يجمع بيانات صوتية من الأطفال ولماذا، ومع من تُشارَك (هنا: Groq كخدمة تقييم خارجية — قبل 2026-09-30 كانت RunPod). ⚠️ **ملاحظة إضافية بعد التحول لـ Groq:** سياسة الاحتفاظ/الخصوصية الخاصة بـ Groq لبيانات الصوت المُرسَلة عبر API لم تُراجَع رسميًا هنا — يُنصح بمراجعتها مباشرة من موقع Groq (`console.groq.com` وسياسة الخصوصية هناك) قبل إتمام إفصاح Data Safety، بما أن هذه الخدمة تستقبل الآن أصوات أطفال فعليًا.
- **سياسة "Designed for Families"** في Google Play، إن كان التطبيق مصنّفًا ضمنها.
- قوانين مثل **COPPA** (أمريكا) إذا كان الجمهور يشمل أطفالًا أمريكيين، والتي تشترط موافقة صريحة وقابلة للتحقق من ولي الأمر (verifiable parental consent) قبل جمع أي بيانات صوتية من طفل دون 13 سنة.

هذا **ليس اعتراضًا على القرار ولا طلبًا لتغييره** — هو فقط تأكيد أن القرار موجود ومقصود، ولازم يُواكَب بخطوة إفصاح/موافقة رسمية وقت الإطلاق حتى لا يُرفَض التطبيق في مراجعة المتجر أو يُسبب مشكلة قانونية لاحقًا. هذه الخطوة (الإفصاح + الموافقة) هي التي تحتاج قرارًا/تنفيذًا من مالك المنتج، وليست شيئًا يُحسم في الكود.

للسياق فقط، ولضمان الشفافية الكاملة، فإن `ai/GUARDRAILS.md` في هذا المستودع (المكتوب قبل هذا القرار) ينص على عكس هذا صراحة — وبناءً على ما تقدّم، يبدو أن الأنسب هو **تحديث `ai/GUARDRAILS.md` نفسه** ليعكس القرار الفعلي المعتمد الآن، بدل تركه يصف سلوكًا لا يطابق الواقع:

| قاعدة في `ai/GUARDRAILS.md` | ما يفعله السيرفر فعليًا الآن |
|---|---|
| "Presence only. The teacher never says a recitation was right or wrong, never scores it, never shows a grade." | السيرفر **يُقيّم فعليًا** تلاوة/حفظ الطفل (تشابه نصي + تقييم صوتي اختياري عبر Groq) ويُظهر له ردود مثل "ما شاء الله! تلاوتك ممتازة" أو "قريب جدًا! نحاول مرة أخرى" — أي تصحيح وتقييم مباشر، عكس مبدأ "الحضور فقط بدون تصحيح" |
| "Prefer on-device processing for all live audio... Live mic audio is not stored and not sent to third parties." | صوت الطفل **يُرسَل فعليًا لخدمة خارجية (Groq، سابقًا RunPod)** للتقييم، **ويُخزَّن دائمًا** في قاعدة بيانات السيرفر (جدول `manara_voice_samples`) — هذا بناءً على طلب صريح من صاحبة الحساب لتدريب نموذج لاحقًا، لكنه يخالف هذا البند حرفيًا |
| "Any third-party AI service must be declared in Play Data Safety and must not train on children's data. Get approval before adding one." | Groq (تقييم صوتي، سابقًا RunPod) وAnthropic (توليد الكلام) هما خدمتان خارجيتان تُستخدَمان فعليًا دون أن يظهر في الكود أي إشارة لموافقة/إفصاح Play Data Safety مُسبق |
| "No open-ended chat/free-form generation shown to the child." | كلام المعلّم في معظم المراحل **مُولَّد فعليًا بذكاء اصطناعي توليدي (LLM حر)** وليس بنكًا ثابتًا من جمل مُعتمدة مسبقًا كما يصف `ai/CONTRACT.md` (قسم "Teacher-line bank") |

**الخلاصة:** لا شيء هنا يمنع المضي في ربط تطبيق فلاتر بهذا الـ API كما هو موثَّق أعلاه للتطوير والاختبار على `dev-v2` — هذا آمن تمامًا ولا يمس أي بيئة إنتاج. النقطة الوحيدة المطلوبة قبل الإطلاق الفعلي للمستخدمين على المتجر هي استكمال خطوة الإفصاح/الموافقة المذكورة أعلاه (Google Play Data Safety + موافقة ولي الأمر)، وتحديث `ai/GUARDRAILS.md` ليطابق القرار الفعلي المعتمد.

## 7. مثال عملي بلغة Dart/Flutter للربط السريع

هذا القسم كود جاهز (وليس مجرد وصف) عشان يبدأ مطوّر الفلاتر مباشرة بدون لبس. يستخدم حزمة `http` القياسية (`pubspec.yaml`: `http: ^1.2.0`) ومشغّل صوت مثل `audioplayers` أو `just_audio` لتشغيل تلاوة القرآن ورد `/speak`.

### 7.1 عميل بسيط للمحادثة (`/agent/start` و `/agent/message`)

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

class GharsahAgent {
  static const base = 'https://manara-backend-dev.onrender.com'; // بيئة التطوير فقط
  String? sessionId;

  Future<Map<String, dynamic>> start({
    required String mode,       // "quran" أو "hadith"
    required String gender,     // "boy" أو "girl"
    required String deviceId,   // معرف ثابت للجهاز — احفظيه محليًا (SharedPreferences)
    String childName = 'يا بطل',
  }) async {
    final res = await http.post(
      Uri.parse('$base/agent/start'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({
        'mode': mode,
        'gender': gender,
        'device_id': deviceId,
        'child_name': childName,
      }),
    );
    final data = jsonDecode(utf8.decode(res.bodyBytes)) as Map<String, dynamic>;
    sessionId = data['session_id'] as String;
    return data;
  }

  Future<Map<String, dynamic>> sendMessage(String text) async {
    final res = await http.post(
      Uri.parse('$base/agent/message'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'session_id': sessionId, 'text': text}),
    );
    if (res.statusCode == 404) {
      // الجلسة انتهت (إعادة تشغيل السيرفر أو مرور وقت طويل) — أعد /agent/start
      throw SessionExpiredException();
    }
    return jsonDecode(utf8.decode(res.bodyBytes)) as Map<String, dynamic>;
  }
}

class SessionExpiredException implements Exception {}
```

### 7.2 التعامل مع الرد — حسب `expects`

```dart
void handleResponse(Map<String, dynamic> r) {
  final say = r['say'] as String;              // اعرضيه في فقاعة كلام المعلّم + مرّريه لـ /speak
  final expects = r['expects'] as String;       // "text" | "continue" | "repeat" | "choice" | "none"
  final quickReplies = (r['quick_replies'] as List).cast<String>();
  final actions = (r['actions'] as List).cast<Map<String, dynamic>>();

  for (final a in actions) {
    switch (a['type']) {
      case 'show_ayat':
        // اعرضي نص الآيات/الحديث: a['ayat'] (List<String>), a['current'] لتمييز الآية الحالية
        break;
      case 'play_all':
      case 'play_ayah':
        // شغّلي رابط/روابط mp3 مباشرة بمشغل صوت عادي — تلاوة حقيقية، ليست AI
        break;
      case 'set_step':
        // غير مستخدم حاليًا في أي واجهة — تجاهليه بأمان
        break;
    }
  }

  switch (expects) {
    case 'text':
      // افتحي حقل الكتابة، أو تعرّف صوت الجهاز (speech_to_text) وأرسلي الناتج كنص
      break;
    case 'continue':
      // زر "أكمل" + إمكانية سؤال حر — كلاهما نص عادي إلى sendMessage()
      break;
    case 'repeat':
      // سجّلي صوت الطفل، ثم إما (أ) حوّليه لنص محليًا وأرسليه كنص عادي [الأبسط والأسرع]
      // أو (ب) ارفعيه لـ /agent/score-recitation (انظر 6.3) للتقييم عبر Groq
      break;
    case 'choice':
      // اعرضي quickReplies كأزرار اختيار فقط
      break;
    case 'none':
      // انتهت الجلسة — اعرضي زر "ابدأ جلسة جديدة"
      break;
  }
}
```

  } else {
    // فشل (JSON): {"audio": null, "note": "no_key" | "tts_error" | "empty"}

### 7.5 نظام device-token الجديد (اختياري/إضافي) — `POST /agent/device-token`

⚠️ **جديد 2026-10-01.** إضافة أمان اختيارية لا تكسر أي كود قائم — إذا لم تستدعيها، كل شي يستمر يعمل كما كان. تحمي حاليًا `POST /agent/actions/done` فقط.

```dart
import 'package:shared_preferences/shared_preferences.dart';

class GharsahAgent {
  // ... (كما في 7.1، أضيفي الحقول التالية للكلاس)
  String? deviceToken;

  Future<void> claimDeviceToken(String deviceId) async {
    final prefs = await SharedPreferences.getInstance();
    final existing = prefs.getString('device_token');
    if (existing != null) { deviceToken = existing; return; } // سبقت المطالبة

    final res = await http.post(
      Uri.parse('$base/agent/device-token'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'device_id': deviceId}),
    );
    if (res.statusCode == 200) {
      final data = jsonDecode(utf8.decode(res.bodyBytes)) as Map<String, dynamic>;
      deviceToken = data['token'] as String; // يُعرض مرة واحدة فقط من السيرفر — احفظيه فورًا
      await prefs.setString('device_token', deviceToken!);
    } else if (res.statusCode == 409) {
      // تمت المطالبة بتوكن لهذا device_id من قبل (ربما من تثبيت آخر) — تجاهلي بأمان
    }
  }

  Future<void> markActionDone(String deviceId, int hadithId) async {
    final headers = {'Content-Type': 'application/json'};
    if (deviceToken != null) headers['X-Device-Token'] = deviceToken!;
    await http.post(
      Uri.parse('$base/agent/actions/done'),
      headers: headers,
      body: jsonEncode({'device_id': deviceId, 'hadith_id': hadithId}),
    );
  }
}
```

**ملخص الخطوات الصحيحة للربط (بالترتيب):**
1. عند بدء الدرس: `POST /agent/start` بـ `device_id` ثابت للجهاز.
2. لكل رد من المعلّم: اعرضي `say` نصًا + شغّليه صوتًا عبر `POST /speak` (مع fallback لصوت الجهاز عند الفشل)، ونفّذي `actions[]`.
3. حسب `expects`: اجمعي رد الطفل (كتابة/صوت) وأرسليه دائمًا كنص عادي إلى `POST /agent/message` — هذا يكفي لتشغيل التطبيق بالكامل حتى بدون الخطوة 4.
4. **اختياري**: لمرحلة `expects=="repeat"` فقط، ارفعي الصوت أيضًا إلى `POST /agent/score-recitation` للحصول على نسخ صوتي أدق عبر Groq، ثم أرسلي `transcription` الناتج إلى `/agent/message` كأنه نص الطفل.
5. عند أي `404` من `/agent/message` أو `/agent/score-recitation`: أعيدي `POST /agent/start` من جديد. عند أي `429`: انتظري قليلاً وأعيدي المحاولة (حدود طلبات جديدة، §0).
6. **اختياري (ميزات إضافية بعد أن يعمل الأساس):** شاشة "مشاريعي" عبر `GET /agent/actions` + `POST /agent/actions/done` (§1، وحماية device-token اختيارية في §7.5)، شاشة تسميع/اختبار حفظ عبر `GET /agent/taseem/status` (أو `htaseem`) ثم `POST /agent/taseem/start` (أو `htaseem`) (§1)، وزر رجوع لمرحلة سابقة عبر `POST /agent/jump` (§1). لا شيء من هذه الثلاثة ضروري ليعمل الدرس الأساسي.
